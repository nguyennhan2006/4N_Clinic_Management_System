\chapter{Kiểm thử phần mềm}

\section{Mục tiêu kiểm thử}

Mục tiêu kiểm thử là xác nhận hệ thống đáp ứng các yêu cầu đã chốt, các business rules quan trọng được thực thi đúng và các luồng nghiệp vụ chính hoạt động ổn định khi frontend, backend và database được tích hợp. Chương này trình bày chiến lược kiểm thử, bằng chứng test hiện có, kế hoạch test Phase 1, kế hoạch test thủ công Phase 2 và các giới hạn cần trình bày trung thực.

\section{Chiến lược kiểm thử}

Nhóm kết hợp nhiều hình thức kiểm thử:

\begin{itemize}
    \item Kiểm thử E2E backend cho các luồng lõi Phase 1.
    \item Kiểm thử API thông qua Swagger/Postman hoặc e2e tests.
    \item Kiểm thử giao diện thủ công theo từng vai trò.
    \item Kiểm thử tích hợp giữa frontend, backend và database.
    \item Kiểm thử hồi quy Phase 1 sau khi mở rộng Phase 2.
\end{itemize}

\ReportFigure{figures/ch05-testing/testing-strategy.pdf}{Tổng quan chiến lược kiểm thử của hệ thống}{fig:testing-strategy}

\textbf{Ghi chú trung thực:} Codebase hiện có e2e tests cho các luồng lõi Phase 1. Theo log test run được nhóm cung cấp, các test tự động đã chạy thành công 220/220. Phase 2 cần bổ sung manual test evidence hoặc automated tests trong tương lai.

\section{Kiểm thử giao diện}

\begin{itemize}
    \item Đăng nhập thành công với 5 roles chính: ADMIN, DOCTOR, RECEPTIONIST, CASHIER, MANAGER.
    \item Sidebar hiển thị đúng theo role; route không đủ quyền redirect sang /403.
    \item Form validation hiển thị lỗi required, format và business conflict.
    \item Loading, empty, error, success state hoạt động đúng.
    \item VND format và date format đúng.
    \item Dark mode toggle hoạt động và lưu qua localStorage.
    \item Logout xóa token và redirect về login.
    \item Không hiển thị passwordHash ở bất kỳ màn hình nào.
\end{itemize}
